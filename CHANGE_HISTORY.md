## 2026-10-19 — Complete Dummy Data Removal Across All Database Stores & Switzerland Finds Fix

### 1. Date and Title
* **Date:** 2026-10-19
* **Title:** Fix Incomplete Dummy Data Removal Across the Entire Database & Switzerland Finds Survival

### 2. Reason
When users confirmed "Remove Dummy Data" from Settings, Switzerland Find items (“The Chedi Andermatt Alpine Haven”, “Grindelwald First Cliff Walk & Tissot Bridge”, and “Fondue Chalet Ferdinand with Matterhorn Panorama”) remained behind in the Switzerland country collection. Additionally, unedited sample country dossiers (`switzerland`, `japan`, `kazakhstan`) and companion records (sample recipes, transport legs, base ingredient prices) survived cleanup or left orphaned data.

### 3. Previous Behaviour
* `removeDummyData()` audited trips, places, collections, events, bookings, expenses, essentials, documents, and journals, but omitted `db.countries` and companion tables (`transportLegs`, `recipes`, `baseIngredientPrices`, `tripMealPlans`, `tripGroceryItems`, `tripIngredientOverrides`).
* In `src/db/provenance.ts`, `BASELINE_SAMPLE_COLLECTIONS` held legacy baseline titles (`'Restaurant Taverne Traditional Swiss Fondue'`, `'Victoria-Jungfrau Grand Hotel & Spa'`, `'Jungfraujoch – Top of Europe High Alpine Sphinx'`). When compared against the active titles generated by `seedData.ts`, `isCollectionItemEdited()` falsely concluded the items were user-edited, preserving them and detaching them to the Switzerland inbox.
* `SAMPLE_COLLECTION_IDS` was missing the 6 active sample IDs (`col-2`, `col-3`, `col-inbox-1`, `col-inbox-2`, `col-kz-1`, `col-inbox-3`).
* Empty sample country dossiers lingered in `db.countries` after trips were deleted.

### 4. New Behaviour
* All records created by the sample-data seeder across all 17 Dexie/IndexedDB database stores are completely removed upon confirming "Remove Dummy Data".
* Switzerland collection items (`col-2`, `col-3`, `col-ch-food-1`, `col-ch-stay-1`, `col-ch-place-1`) and independent inbox items (`col-inbox-1`, `col-inbox-2`, `col-inbox-3`) are cleanly identified and deleted when unedited.
* Unedited sample country dossiers (`switzerland`, `japan`, `kazakhstan`) are cleanly pruned from `db.countries` unless the user has personal finds in that country, has a personal trip there, or matches their `dreamCountry` or `homeCountry`.
* Unedited sample recipes (`recipe-shakshuka`, `recipe-garlic-butter-pasta`, `recipe-tokyo-curry`), sample base ingredient prices (14 entries), and sample transport legs are deleted.
* All genuine personal user data, custom trips, custom recipes, custom finds, user-edited sample records, and user profile settings remain strictly intact.
* Running "Remove Dummy Data" a second time (idempotency) cleanly executes with 0 items deleted and 0 side effects.

### 5. Affected Screens and Workflows
* **Settings Screen (`SettingsView.tsx`):** "Remove Dummy Data" workflow and confirmation modal (`RemoveSampleDataModal.tsx`).
* **Finds / Collections Hub (`CollectionView.tsx`):** Switzerland country folder and All Saved Finds inbox are empty of sample data after cleanup, retaining only genuine user finds.
* **Country Dossier Gallery:** Empty sample country folders disappear from the country gallery when no user data links to them.
* **Travel Companion & Recipe Library:** Sample recipes and sample ingredient catalog prices are purged from global lists unless customized by the user.

### 6. Files and Components Modified
* `src/types/index.ts`: Added `isSample?: boolean; isEdited?: boolean;` metadata fields to `CountryDossier` and `BaseIngredientPrice`.
* `src/db/seedData.ts`: Attached `isSample: true` to seeded country dossiers and base ingredient price entries.
* `src/db/provenance.ts`:
  * Expanded `SAMPLE_COLLECTION_IDS` to include all 15 active sample collection IDs while retaining legacy IDs.
  * Added `SAMPLE_RECIPE_IDS`, `SAMPLE_TRANSPORT_LEG_IDS`, `SAMPLE_BASE_INGREDIENT_PRICE_IDS`, `SAMPLE_COUNTRY_IDS`, and `SAMPLE_COUNTRY_NAMES`.
  * Updated `BASELINE_SAMPLE_COLLECTIONS` with `titles: string[]` support to seamlessly recognize both active and legacy sample titles as unedited baseline records.
  * Extended `inspectDummyDataForRemoval()` and `removeDummyData()` to audit and atomic bulk-delete unedited dummy data across all 17 IndexedDB stores.
  * Implemented country protection rules preserving dossiers linked to user finds, user trips, `dreamCountry`, or `homeCountry`.
  * Added fallback helper `safeGetTableRecords()` preventing `MissingAPIError` in Node/test environments.
* `src/components/settings/RemoveSampleDataModal.tsx`: Resets `activeTripId(null)` if the currently active trip was deleted during cleanup.
* `src/tests/dummyRemovalAndTripDelete.test.ts`: Added Test Suites 7, 8, 9, and 10 testing all 15 collection items, legacy title recognition, country pruning vs dream country protection, full-store cleanup, and idempotency.
* `PRD.md`: Documented Release 2.8.1 with complete technical details and verification results.

### 7. Technical Details
* `db.transaction('rw', allTables, ...)` wraps all 17 database tables in a single atomic Dexie transaction, ensuring complete rollback safety if any step fails.
* Edit detection distinguishes between user-edited sample records (which must be preserved) and pristine sample data across all stores using baseline matching dictionaries (`BASELINE_SAMPLE_TRIPS`, `BASELINE_SAMPLE_COLLECTIONS`, `BASELINE_SAMPLE_RECIPES`, etc.).
* Foreign key detachment: If a user created or edited a collection item or journal entry attached to a deleted dummy trip, the trip relationship is safely cleared (`tripId = undefined`, `status = 'inbox'`, destination preserved) instead of deleting the user's item.
* Country pruning logic checks `preservedCountryNames` compiled from:
  1. `userProfile.dreamCountry`
  2. `userProfile.homeCountry`
  3. `userTrips[].country` and detected destinations
  4. `userCollections[].country`
  5. Any collection items detached during the cleanup transaction.

### 8. Data and Compatibility Impact
* **Schema Impact:** None. Dexie schema version remains unchanged; `isSample` and `isEdited` are optional in-memory / document-level attributes.
* **Storage & Migration:** Fully backward-compatible. Legacy records without `isSample` are recognized via deterministic sample ID sets and baseline title arrays.
* **User Data Safety:** Zero risk to personal travel data. Profile identity (`travelnest_user_profile`), dream country, home country, and genuine user records are strictly preserved.

### 9. Verification Results
* **Targeted Automated Test Suite (`src/tests/dummyRemovalAndTripDelete.test.ts`):** 118 assertions passed, 0 failed across 10 test suites.
* **Full Automated Test Suite (`npm test`):** 9 test suites passed, 0 failed (480+ total assertions).
* **Static Analysis & Linting (`npm run lint`):** `oxlint` passed with 0 errors across 91 source files.
* **Production Build (`npm run build`):** `tsc -b && vite build` completed successfully with 0 TypeScript or bundling errors.
* **Physical Device / Emulator Testing:** None performed (in strict adherence to constraints).

### 10. Limitations
* Does not delete records where the user manually created a custom item with the exact same ID as a sample entity (prevented by UUID generation in user flows).
* If a user manually edited a sample item (e.g. modified the title or notes), it is intentionally treated as personal data and preserved in the inbox.
